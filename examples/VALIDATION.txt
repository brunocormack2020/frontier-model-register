The tests cover source parsing and filtering, configuration-specific identities,
missing versus zero, provider and mapping boundaries, source integrity, unavailable
sources, stale/forged reviews, history retention, conditional scope, bank decision
binding, HTML/Excel injection and existing Confluence publishing behavior. Focused
in-memory checks also verified raw-source acknowledgments and hashes, rejection,
stale queue handling and all four coding/SOC HTML combinations. Those checks left
the operational state unchanged.

Live public benchmark bytes were downloaded with curl through the environment's
configured proxy and validated with the delivered parsers. HTTPX transport was
checked with controlled fixtures. The default HTTPX live path was not tested end
to end because the environment lacks the optional SOCKS dependency. If your company
uses a SOCKS proxy, install the approved httpx[socks] extra; keep TLS verification
on and test your network and certificate trust. See README for setup details.

No authenticated provider catalog request, generative model invocation, execution
of benchmark workloads or live Confluence update was performed. The package can
generate and publish managed Confluence content; its destination and identity must
be configured and checked in the company's environment. Publishing defaults to a
dry run. Local hashes/history are not a tamper-proof audit service. The script does
not implement the bank's complete policy or autonomously approve models.
